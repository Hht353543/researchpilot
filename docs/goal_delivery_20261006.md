## 六类资料与真实模型复测

复用 [既有六类合成资料](../eval/personal_acceptance.json)，另测否定追问和收入增长追问。每题单独知识库；追问继承父任务及相同资料 ID。没有使用用户正式资料。

三轮统一使用保存连接的 `deepseek-flash`，响应也均记录为此别名；temperature=0.1、presence/frequency penalty=0、max_tokens=1200、top_k=4、max_iterations=1、max_retries=1、请求超时120秒、任务超时600秒、hash embedding。Agent 内部各步骤仍有自己的输出额度，`max_tokens=1200` 不等于每一步的实际输出上限。服务没有提供不可变模型版本或采样种子，缓存、上游负载、执行顺序没有控制。

| 轮次 | 六个初始问题：调用 / tokens / 平均耗时 | 含两次追问：调用 / tokens / 平均耗时 |
| --- | --- | --- |
| 摘要与引用修复后，30,000 预算 | 46 / 102,410 / 20.584秒 | 64 / 158,266 / 23.287秒 |
| 收紧步骤，60,000 预算 | 46 / 101,614 / 19.448秒 | 63 / 146,927 / 20.744秒 |
| 补足计算引用导致的年份金额遗漏，60,000 预算 | 46 / 102,597 / 19.584秒 | 61 / 142,933 / 19.950秒 |

最终六题调用数与第一轮相同、tokens略增，不能据八题总量声称六题普遍节省成本。含追问的总量减少15,333 tokens，但这是单次本机小样本。最终八题均 completed、errors=[]；自动 quality 为4个 succeeded、4个 degraded。这些标签不是正确率。

每次 HTTP 响应 usage、任务 metrics 与 LLM spans 的 tokens 已逐题对账一致，包含跨预算响应。最终六题最大21,569 tokens，收入追问23,030；第一轮同一追问实际31,792 tokens，跨30,000预算后丢失计算答案。因此实验与演示使用60,000预算，不凭六份短资料降低通用桌面160,000默认预算。单次响应仍可能跨阈值；已有用量会完整记录并阻止后续调用。

步骤调整来自实际观察：Planner 不再要求为简单资料题额外创建元数据/假想产品策略子任务；Writer 的分析输入排除 synthesis 步骤，避免再生成一章综合复述。Verifier、Critic 与报告事实复核均保留。后两轮允许调用已有安全 AST 计算器，关闭第一轮增长追问的工具 allow-list 错误。固定参数、源码/资料哈希、逐步调用和用量见 [机器记录](../output/goal-20261006/review-summary.json)；原始运行分别在 `output/goal-20261006/live-fixed`、`live-tuned`、`live-final`，没有覆盖失败产物。
