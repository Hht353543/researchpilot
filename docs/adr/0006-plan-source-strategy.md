# ADR-0006: 计划来源策略（模型计划 vs 确定性计划）

- 状态：提案（待决定）
- 日期：2026-09-16

## 背景

Planner 有两种产出方式：

1. **模型计划**：让模型按 Schema 拆解子任务、选工具、写子问题；
2. **确定性计划**：`PlannerAgent._fallback_plan()`，按问题类型套一组固定的子问题与工具。

确定性计划原本只是"模型失败时的兜底"，但 2026-09-15 的真实评测显示它可能更好用：
当时因为 `Subtask.intent` 的严格枚举与真实模型不兼容，35/35 任务的计划都走了兜底，
而那次的检索指标反而更好。修掉该缺陷后模型计划才真正生效，指标随即下降。

## 证据（同一套 35 条用例、同一套判分代码，deepseek-chat）

| 指标 | 全部走确定性计划（修复前） | 模型自己的计划（修复后） |
| --- | --- | --- |
| Task Success | 25/35 (71.4%) | 24/35 (68.6%) |
| Retrieval Recall@6 | 91.7% | 90.6% |
| Context Relevance | 28.8% | 9.2% |
| 平均延迟 | 111.1s | 184.6s |
| Token / 成本 | 2.06M / $1.16 | 3.11M / $1.75 |
| 单任务检索文档数 | 较少（受固定子问题约束） | 更多（模型自由发散） |

两条附带观察：

- 修复前的引用正确率 90.3% 有回退写作器参与，不能作为模型能力，因此上表未把它当作计划优劣的依据；
- 两组数字之间还夹着写作器与状态语义的修复，**不是干净的 A/B**。要判断计划来源本身的优劣，
  必须在其它条件不变的前提下只切换计划来源。

## 可选方案

| 方案 | 做法 | 优点 | 代价 |
| --- | --- | --- | --- |
| A 保持现状 | 一直用模型计划 | 行为诚实，指标归属模型；对任意问题泛化 | 本项目语料上检索精度低、更慢更贵 |
| B 默认确定性 | 默认走确定性计划，模型计划可选 | 本语料上检索最好、最省成本 | 只对这份数据集友好，换问题/换语料会退化，等于放弃 Planner 的意义 |
| C 可切换 | 新增 `RESEARCHPILOT_PLAN_MODE=model|deterministic|auto`，默认值不变（model） | 能跑干净的 A/B；部署方按场景选择 | 多一个配置面与测试面 |
| D 混合 | 模型负责子任务与工具选择，检索查询用固定模板扩展 | 兼顾覆盖面与查询质量 | 实现最重，需要重新训练/调参式验证 |

## 建议

先做 C（只加开关与测试，默认行为不变），用它跑一次干净的 A/B：同一模型、同一预算、
仅切换计划来源，得到"计划来源单独对指标的影响"。拿到干净数据后再决定默认值；
如果确定性计划的优势只体现在这份合成语料上，就保留 model 为默认，把 deterministic 作为
评测与对照工具，而不是生产默认值。

至于 D，建议等干净的 A/B 出来再评估：如果差距主要来自"模型子问题太发散"，
那么给模型计划加一层查询扩展模板，可能比整体回退更划算。
