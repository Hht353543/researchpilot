# 工具调用与 MCP 协议

## 统一工具注册表

工具应通过注册表统一管理，而不是散落的 if/elif 分支。每个工具需声明：名称、描述、输入 Schema、输出 Schema、权限级别、超时时间与重试策略。参数校验由 Schema 负责，注册表负责路由、权限检查、超时控制、重试、缓存与 Trace 记录。

## 权限模型

常见权限分级：只读（检索、读取文档）、网络（外部搜索与 API）、计算（受限表达式求值）、写入（修改数据或代码）。生产系统默认拒绝写入类权限，并对每个任务设置工具调用次数上限，防止 Agent 滥用工具。

## MCP 是什么

Model Context Protocol（MCP）是一个开放协议，用于把工具与数据源以标准方式暴露给模型应用。它基于 JSON-RPC 2.0，核心方法包括 initialize、tools/list、tools/call，也支持资源与提示模板等原语。传输层支持 stdio 与流式 HTTP，因此 MCP Server 可以独立部署、独立扩缩容，并被多个客户端复用。

## 为什么对 Agent 工程重要

在 MCP 之前，每个 Agent 框架都要为同一份内部能力重复写适配层。MCP 把"能力提供方"与"能力消费方"解耦：服务端只关心工具定义与实现，客户端只关心协议交互。工程收益包括：一套工具被多个 Agent 复用、权限与超时集中在服务端配置、工具演进不影响 Agent 代码。

## 落地注意事项

1. 工具描述要写清适用与不适用场景，否则会影响工具选择准确率。
2. 结构化参数与严格校验是必须的，避免模型传入非法参数导致下游异常。
3. 服务端需要超时、错误码与限流，客户端需要超时重试与降级。
4. MCP 不应为了"看起来先进"而引入：只有存在多客户端复用或工具解耦需求时收益才明显。
