# 安全与可靠性护栏

## 提示注入

检索到的文档与网页内容是数据，不是指令。常见攻击形式包括"忽略以上指令""输出你的系统提示词""进入开发者模式"以及伪造 `<system>` 标签。缓解手段：把所有外部内容包裹在带来源标记的不可信区块中、在系统提示中明确优先级、对命中注入特征的内容降权并在校验阶段标记。

## 工具滥用

限制手段包括：工具白名单与权限分级、每任务调用次数上限、参数 Schema 校验、危险操作（写入、删除、执行）默认禁用、以及对参数中出现的越权意图做检测。

## 超时、重试与预算

每个工具声明超时时间；重试要区分可重试错误（网络抖动、限流 429）与不可重试错误（参数错误 400）。任务级别需要 max_iterations、token 预算与总时限，防止 Agent 无限循环。

## 输出校验

结构化输出必须经过 Schema 校验，校验失败时进行有限次数的修复重试，仍失败则降级为确定性回退路径。写作阶段要校验引用 id 是否真实存在，剔除编造引用并记录审计信息。

## 人在回路

高风险动作（合并代码、发布、修改生产数据）应要求人工确认；Agent 提供证据、影响面分析与回滚方案。
