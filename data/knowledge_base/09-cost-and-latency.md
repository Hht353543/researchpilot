# 成本与延迟工程

## 成本构成

多 Agent 系统的成本主要来自：模型调用（输入与输出 token）、检索与重排、外部搜索 API、以及重试与失败重跑。输入 token 往往被低估：把全部证据塞进写作提示会线性放大成本。

## 控制手段

模型分层路由：规划与校验使用强模型，抽取与格式化使用小模型。

缓存：对相同检索查询与相同工具参数做 TTL 缓存；对稳定的系统提示启用提示缓存。

预算：为每个任务设置 token 预算与最大迭代次数，超预算时提前收敛并标记 degraded。

并发：独立子任务的检索与抽取可以并行执行，降低端到端延迟。

## 延迟预算

交互式场景通常要求首字节快速返回，因此会先给计划与检索进度、再给最终报告。批处理场景更关心单位任务成本与吞吐。

## 度量

必须记录每个 Agent、每次 LLM 调用、每次工具调用的延迟与 token，才能定位瓶颈。缺少分阶段指标时，优化往往靠猜。
